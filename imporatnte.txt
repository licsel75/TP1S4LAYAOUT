13. Flujo completo de una petición (ejemplo: agregar superhéroe)
El usuario completa el formulario en addSuperheroe.ejs.

El navegador envía un POST /heroes/agregar.

Express recibe la petición y la pasa por los middlewares.

Las rutas redirigen al controlador createSuperheroeController, pero antes pasan por las validaciones.

Si los datos no son válidos, se muestra nuevamente el formulario con errores.

Si los datos son válidos, el controlador llama al servicio createSuperheroe.

El servicio procesa los datos (ej: convierte poderes de string a array) y llama al repositorio.

El repositorio guarda en MongoDB usando el modelo.

El controlador redirige al dashboard.

El dashboard consulta nuevamente todos los héroes y los muestra actualizados.

🧠 Resumen de lo que has aprendido
1. Node.js y Express
Node.js permite ejecutar JavaScript fuera del navegador, en el servidor.

Express es un framework que facilita crear servidores web y APIs.

El servidor se inicia con app.listen() y escucha peticiones en un puerto (ej: 3005).

2. Middlewares
Son funciones que se ejecutan entre la petición y la respuesta.

Se usan con app.use().

Ejemplos: express.json() (parsea JSON), express.urlencoded() (parsea formularios), method-override (habilita PUT/DELETE en formularios HTML).

El orden de los middlewares importa: se ejecutan en el orden en que se declaran.

3. MVC (Modelo - Vista - Controlador)
Modelo: define la estructura de los datos y se conecta a la base de datos (Mongoose).

Vista: es la interfaz que ve el usuario (archivos .ejs con HTML + JavaScript).

Controlador: orquesta las peticiones, llama al servicio y decide qué vista renderizar.

4. Capas adicionales (arquitectura más profesional)
Repositorio: capa que habla directamente con la base de datos. Separa el acceso a datos de la lógica de negocio.

Servicio: contiene la lógica de negocio. Usa el repositorio y procesa los datos antes de guardarlos.

Validaciones: reglas que verifican que los datos de entrada sean correctos (express-validator).

5. EJS (Embedded JavaScript)
Motor de plantillas que permite incrustar JavaScript en HTML.

Se usa con res.render('vista', { datos }).

Sintaxis: <%= variable %> (muestra valor), <% codigo %> (ejecuta lógica), <%- include('partial') %> (reutiliza partes de la vista).

6. MongoDB y Mongoose
MongoDB es una base de datos NoSQL (almacena documentos en formato JSON).

Mongoose es una librería que facilita conectar Node.js con MongoDB, definir esquemas y validar datos.

7. CRUD completo
Create → POST para agregar nuevos superhéroes.

Read → GET para listar superhéroes en el dashboard.

Update → PUT (con method-override) para editar superhéroes.

Delete → DELETE (con fetch) para eliminar superhéroes con confirmación.

9. Patrón Repository con Interfaz
IRepository.mjs define un contrato (los métodos que debe tener todo repositorio).

SuperHeroRepository.mjs implementa esos métodos usando Mongoose.

Se exporta una única instancia (singleton) para reutilizar en toda la app.

10. Validaciones con express-validator
Se definen reglas con body('campo').isLength().withMessage().

Se verifica si hay errores con validationResult(req).

Si fallan, se vuelve a renderizar el formulario con los mensajes de error.

11. Flujo de una petición (ejemplo: agregar superhéroe)
Usuario completa formulario → POST /heroes/agregar.

Pasa por middlewares → rutas → validaciones.

Si hay error → vuelve al formulario.

Si todo bien → controlador → servicio → repositorio → MongoDB.

Redirige al dashboard → se ve la lista actualizada.

12. Conceptos clave adicionales
method-override: permite usar PUT y DELETE desde formularios HTML.

fetch(): se usa desde el frontend para hacer peticiones DELETE sin necesidad de formulario.

Partial EJS: fragmentos de vista reutilizables (header, footer).

Singleton: una sola instancia de una clase que se reutiliza (como el repositorio).
